1. Executive Summary

A source-code-level UI/UX audit was conducted on the SST-ERP Super Admin Portal to identify usability issues, inconsistencies, missing interface behaviours, and areas requiring improvement.

  • Pages Audited: 21 Super Admin pages and dynamic section modules.
  • Workflows Verified: Authentication callback, login redirects, and 8 shared subscription destinations.
  • Files Evaluated: 47 relevant files inventoried; 27 files examined in source-level detail.
  • Total Findings: 7 confirmed issues (3 High severity, 4 Medium severity).

3. Source-Confirmed Findings & Required Corrections

SUI-001: Broken Subscription Sub-Navigation in Super Admin Shell High Severity
components/super-admin/super-admin-shell.tsx (Lines 25–34, 62–71)

Problem Description: When accessing /subscriptions, the sidebar displays a secondary Subscription management navigation menu. However, every item points to dead in-page hash anchors (e.g. /subscriptions#billing-overview, /subscriptions#plan-management, etc.) instead of the actual Next.js App Router sub-routes (/subscriptions/plans, /subscriptions/institutions, /subscriptions/payments, /subscriptions/invoices, /subscriptions/renewals, /subscriptions/reports). Because /subscriptions/page.tsx does not render all sections on one scrollable page, clicking any of these links fails to navigate.

Required Correction: Update subscriptionNavigation in super-admin-shell.tsx to link directly to the real routes (/subscriptions/plans, /subscriptions/institutions, /subscriptions/payments, etc.) and configure active item highlighting.

SUI-002: Auth Callback Drops Error Context and Restricts Valid Sub-Paths High Severity
app/super-admin/auth/callback/route.ts (Lines 7–14) & app/super-admin/login/page.tsx (Lines 1–5)

Problem Description: When authentication exchange fails, callback/route.ts redirects to /super-admin/login?error=auth_callback. However, login/page.tsx performs an unconditional redirect to /login?role=super-admin, stripping the error query parameter entirely. The user lands on the generic login page with no error indication. Additionally, destination validation logic strictly requires next.startsWith("/super-admin/"), discarding valid destinations like /super-admin (without trailing slash) and /subscriptions.

Required Correction: Forward query search parameters (including error) in app/super-admin/login/page.tsx to /login, and expand the destination whitelist to include /super-admin and /subscriptions*.

SUI-003: Institution Creation Form Discards Feedback & Hardcodes Default Password High Severity
components/super-admin/create-institution-form.tsx (Lines 26–28, 64–67)

Problem Description: The institution creation form is wrapped in a native HTML <details className="sa-card sa-form-disclosure"> element. When submitted, server-side validation errors (state.error) or success notices (state.success) cause re-renders that can leave the disclosure closed, hiding critical feedback from the administrator. Furthermore, line 64 hardcodes a static default password (defaultValue="Password@123") without an eye toggle, password generator, or complexity validation.

Required Correction: Control the <details> open state via React state and force it open on error/success. Remove the hardcoded default password, add a password visibility toggle, and clear form fields upon successful creation.

SUI-004: Dashboard Analytics Line Chart Scaling and Viewport Responsiveness Issues Medium Severity
components/super-admin/dashboard-analytics.tsx (Lines 15–22, 42–50)

Problem Description: In LineChart, values are pre-divided by max before being passed to chartPoints, which then computes Math.max(1, ...values) again, resulting in redundant coordinate math and potential distortion when series are toggled. Additionally, fixed SVG dimensions (viewBox="0 0 760 250") and percentage tooltip positioning cause label overlap and horizontal tooltip clipping on mobile and tablet viewports.

Required Correction: Refactor chartPoints to handle absolute series values directly, add responsive CSS to skip intermediate labels on mobile, and implement boundary-safe tooltip positioning.

SUI-005: Institution Details Actions Lack Confirmation Dialogs and Destructive Safeguards Medium Severity
app/super-admin/(protected)/institutions/[id]/page.tsx (Lines 70–84, 136–163)

Problem Description: High-impact mutations—including Suspend/Activate institution, Archive institution, and Archive division—are executed via direct HTML form submit buttons without modal confirmation dialogs or pending-state spinners. A single accidental click can immediately archive an active institution or division, severing access for all associated users.

Required Correction: Introduce modal confirmation dialogs for destructive actions (requiring name confirmation for archival) and add useFormStatus loading indicators on all buttons.

SUI-006: Dynamic Module Generic Table Lacks Cell Truncation & Has Mojibake Encoding Medium Severity
app/super-admin/(protected)/[section]/page.tsx (Lines 140–155, 179–181)

Problem Description: In modules like audit-logs (Request IDs), settings (JSON payloads), and domains (DNS TXT challenge tokens), long unstructured strings cause horizontal table overflow and disrupt layouts. Furthermore, lines 144 and 150 contain corrupted character sequences (â€”) in source code, rendering visual artifacts instead of clean em-dashes (—).

Required Correction: Replace corrupted â€” sequences with clean UTF-8 em-dashes (—) and apply .sa-cell-truncate CSS utility classes with copy-to-clipboard actions for long identifiers.

SUI-007: Inconsistent Styling & Disjointed Design Paradigms Across Portal Boundaries Medium Severity
app/super-admin/super-admin.css & app/subscriptions/subscriptions.css

Problem Description: The Super Admin Portal uses custom CSS variables (--sa-teal, --sa-navy, --sa-gold) that diverge from the shared institutional portal design system (Tailwind CSS palette and Radix UI). When moving from /super-admin to /subscriptions, button corner radiuses, typography weights, table borders, and card elevations shift noticeably.

Required Correction: Harmonize color tokens, button radiuses, input heights, and elevation shadows between super-admin.css and subscriptions.css to match the SST-ERP corporate design language.

4. Implementation and Verification Requirements

  • All identified High-severity issues (SUI-001, SUI-002, SUI-003) must be addressed first.
  • Medium-severity issues (SUI-004, SUI-005, SUI-006, SUI-007) are resolved subsequently.
  • Existing Super Admin authentication and authorization (requireSuperAdmin) remain intact.
  • Changes must not break shared subscription pages or APIs (/api/subscriptions/*).
  • Navigation and page layouts must remain responsive and accessible across all device breakpoints.
